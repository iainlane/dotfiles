The action installed the requested toolchain and then made it the rustup
default. A `rust-toolchain.toml` in the checkout outranks the default, so the
file kept deciding which compiler ran and the `toolchain` input had no effect.
The action now sets a rustup directory override for the workspace instead,
which the toolchain file does not outrank.

CI could not have caught this. The old matrix wrote the toolchain file only for
the null `rust` entry, so no job ran the same toolchain value both ways, and no
step ever looked at the compiler which came out. `write-toolchain-file` is now
its own matrix dimension, and two new steps read `rustc --version`: one asserts
that the pinned nightly from the toolchain file is not what runs, the other that
a job with neither an input nor a file gets stable. Both would fail on the
previous action.

I committed the change as `fix(toolchain): let the input outrank a toolchain
file`. `actionlint .github/workflows/ci.yml` passes.
